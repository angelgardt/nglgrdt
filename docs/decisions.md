# Журнал решений

Сюда записываются архитектурные решения и новые зависимости: дата, решение, причина.
Новые записи добавляются в конец.

## 2026-10-30 · Astro вместо Vue

**Решение.** Сайт собирается на Astro 7.x с полностью статическим выводом. Прототип на Vue 3 + Vite удалён.

**Причина.** Сайт — это набор статических страниц с данными из файлов. Astro отдаёт готовый HTML без JavaScript-фреймворка в браузере, умеет проверять данные по схемам при сборке и публикуется на GitHub Pages официальным способом. Согласовано в ТЗ, раздел 3.

## 2026-10-30 · Обычный CSS и токены

**Решение.** Стили пишутся на обычном CSS. Все цвета, размеры и отступы — CSS-переменные в `src/styles/tokens.css`. Tailwind и CSS-фреймворки не используются.

**Причина.** Дизайн-система небольшая, владелец знает CSS и хочет менять значения в одном месте. Согласовано в ТЗ, разделы 3 и 7.

## 2026-11-10 · Основная ветка — `master`

**Решение.** Основная ветка репозитория остаётся `master`. Публикация срабатывает на push в `master`, pull request'ы открываются в `master`.

**Причина.** Решение владельца. В первой редакции ТЗ и `CLAUDE.md` была указана `main`; упоминания заменены, чтобы документы не расходились с репозиторием.

## 2026-11-10 · Без линтера

**Решение.** ESLint и oxlint удалены, новый линтер не добавлен.

**Причина.** ТЗ требует только `astro check`, Vitest и Prettier и запрещает лишние зависимости. Если линтер понадобится, это отдельное решение.

## 2026-11-10 · Node.js 24

**Решение.** Версия Node.js зафиксирована в `.nvmrc` (24). Её же использует GitHub Actions. Минимальная версия в `package.json` — та, которую требует Astro 7.

**Причина.** ТЗ требует LTS не ниже 22. Версия 24 — LTS, она уже установлена у владельца через nvm и используется по умолчанию в официальном действии Astro.

## 2026-11-10 · Языки заданы в одном файле

**Решение.** Список языков, язык сайта по умолчанию (`en`), язык данных (`ru`) и переключатель «визитка / полная английская версия» лежат в `src/i18n/config.ts`. Настройка `i18n` в `astro.config.ts` берёт значения оттуда.

**Причина.** ТЗ, раздел 4: переход на полную английскую версию должен быть одной настройкой. В разделе 5 ТЗ сказано, что в списке языков версии 1 только `ru`; это противоречит разделу 4 и задаче I0.2 (английская визитка на `/`), поэтому в списке два языка.

## 2026-11-10 · Воркфлоу из отдельных шагов

**Решение.** В `.github/workflows/deploy.yml` установка, `check`, `test` и `build` — отдельные шаги; публикация — официальными действиями `actions/upload-pages-artifact` и `actions/deploy-pages`. Готовое действие `withastro/action` не используется.

**Причина.** `withastro/action` только ставит зависимости и собирает сайт. ТЗ (раздел 9) требует проверку и тесты до сборки, а задача I0.3 — те же проверки в pull request без публикации.

## 2026-11-10 · Проверка данных до Astro

**Решение.** Все файлы `src/data` проверяются собственным кодом (`src/lib/data-files.ts`) при загрузке `src/content.config.ts`; при ошибке сборка останавливается. Те же проверки идут в `npm test`.

**Причина.** Загрузчик `file()` в Astro 7 при ошибке разметки YAML только пишет предупреждение и продолжает сборку, а ошибки уровня файла (повтор id, основной контакт) не видит вовсе. ТЗ требует, чтобы неверные данные останавливали сборку с названием файла, id записи и поля.

## 2026-11-10 · Схемы в `src/lib/schemas.ts`

**Решение.** Схемы Zod лежат в `src/lib/schemas.ts`, а `src/content.config.ts` только подключает их к коллекциям.

**Причина.** `content.config.ts` импортирует модуль `astro:content`, который недоступен в тестах и скриптах. Отдельный файл позволяет использовать одни и те же схемы в сборке, тестах, отчёте о переводе, JSON Schema и будущей админке.

## 2026-11-10 · Ссылки на теги и позиции — перечислением

**Решение.** Допустимые теги и id позиций подставляются в схему списком, прочитанным из `tags.yaml` и `positions.yaml`.

**Причина.** Неизвестный id становится обычной ошибкой схемы, а редактор подсказывает существующие теги. Встроенная функция Astro `reference()` не останавливает сборку на несуществующей ссылке.

## 2026-11-10 · JSON Schema — свои, в `src/data/schemas`

**Решение.** JSON Schema для редактора создаются из схем Zod встроенным экспортом (`z.toJSONSchema`) и лежат в репозитории. Они обновляются при `npm run dev`, `check`, `build` и командой `npm run schemas`.

**Причина.** Встроенные схемы Astro (`.astro/collections/`) описывают одну запись, а файл данных — это список записей, поэтому редактор их не применит. Новая зависимость не понадобилась: экспорт есть в Zod, который идёт вместе с Astro.

## 2026-11-10 · Поле `context` у позиций

**Решение.** В `positions.yaml` добавлено необязательное поле `context` — мероприятие, курс или проект, в рамках которого была роль.

**Причина.** У 11 записей старого сайта, кроме организации и подразделения, указана третья строка («Весенняя Психологическая Школа», «Семинар по когнитивным исследованиям»). В модели из ТЗ её некуда положить, а терять нельзя. Отступление от ТЗ, ждёт подтверждения владельца (отчёт миграции, раздел 4).

## 2026-11-10 · Контакт по умолчанию невидим

**Решение.** У контактов `visible` по умолчанию `false`.

**Причина.** Запрет 8 ТЗ: скрытые контакты не должны попадать на сайт. Забытое поле не должно публиковать телефон.

## 2026-11-10 · Страница просмотра данных

**Решение.** `/ru/data/` — временная страница без оформления со всеми коллекциями. В собранном сайте она показывает только видимые записи и закрыта от индексации; скрытые записи, невидимые контакты и заметки видны только в `npm run dev`. Страница удаляется в итерации 3.

**Причина.** ТЗ требует в итерации 1 вывести данные простыми списками для проверки, а сайт публичный.

## 2026-11-10 · Сообщения об ошибках данных — на русском

**Решение.** Для Zod включена русская локаль.

**Причина.** Сообщения читает владелец, когда сборка падает из-за данных.
